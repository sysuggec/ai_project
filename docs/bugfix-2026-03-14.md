# Bug 修复总结 - 2026-03-14

> **问题**: Docker 部署后前端页面无法加载数据
> **状态**: ✅ 已修复
> **影响范围**: 所有页面（资源管理、回收站、分享、上传）

---

## 问题概述

在 CloudStudio 环境中使用 Docker 部署项目后，访问页面时浏览器控制台报错：

```
TypeError: Cannot read properties of undefined (reading 'directories')
TypeError: Cannot read properties of undefined (reading 'files')
```

尽管后端 API 返回了正确的数据，但前端页面无法正常显示内容。

---

## 根因分析

### 问题 1: 缺少响应拦截器

项目中的 5 个 API 文件都创建了独立的 axios 实例，但都没有配置响应拦截器：

```
src/frontend/src/api/
├── resource.js   ❌ 缺少拦截器
├── trash.js      ❌ 缺少拦截器
├── file.js       ❌ 缺少拦截器
├── share.js      ❌ 缺少拦截器
└── upload.js     ❌ 缺少拦截器
```

### 问题 2: 重复访问 `.data`

拦截器提取了 `response.data.data` 后，API 函数又访问了 `.data`：

```javascript
// 错误的数据流
后端: { success: true, data: { files: [...] } }
  ↓
axios: response.data = { success: true, data: { files: [...] } }
  ↓
拦截器: return response.data.data = { files: [...] }
  ↓
API 函数: return response.data = undefined  // ❌ { files: [...] }.data = undefined
```

### 问题 3: Composable 检查已不存在的字段

```javascript
// useTrash.js / useShare.js
if (response.success) {  // ❌ success 字段已被拦截器移除
  trashList.value = response.files
}
```

---

## 修复方案

### 修复 1: 统一响应拦截器

为所有 API 文件添加统一的拦截器：

```javascript
api.interceptors.response.use(
  response => {
    if (response.data && typeof response.data === 'object' && 'success' in response.data) {
      return response.data.data ?? response.data
    }
    return response.data
  },
  error => {
    console.error('API Error:', error)
    return Promise.reject(error)
  }
)
```

### 修复 2: 移除 `.data` 访问

修改所有 API 函数：

```javascript
// 修改前
export const getFiles = async () => {
  const response = await api.get('/files')
  return response.data  // ❌
}

// 修改后
export const getFiles = async () => {
  const response = await api.get('/files')
  return response  // ✅
}
```

### 修复 3: 更新 Composable 函数

移除对 `response.success` 的检查：

```javascript
// 修改前
const response = await getTrashList()
if (response.success) {  // ❌
  trashList.value = response.files
}

// 修改后
const response = await getTrashList()
trashList.value = response.files || []  // ✅
```

## 经验教训

### 1. 代码一致性
- 多个 API 文件使用相同模式时，应确保实现一致
- 建议创建统一的 API 实例，避免重复配置

### 2. 数据流追踪
- 在开发新 API 时，应完整追踪数据流向
- 从后端响应 → axios 拦截器 → API 函数 → Composable → 组件

### 3. 测试覆盖
- API 响应处理逻辑应有单元测试
- 建议添加 E2E 测试覆盖关键 API 调用

### 4. 文档维护
- 及时更新 API 规范文档
- 记录重要的 bug 修复和技术决策
