## 问题列表

### 问题 1: 分享过期时间显示错误

**症状**: 分享列表显示刚创建的分享"已过期"

**根因**: PHP 时区设置问题
- Docker 设置了 `TZ=Asia/Shanghai`（系统时区）
- PHP 的 `new \DateTime()` 使用默认 UTC 时区
- 前端 `new Date()` 使用浏览器本地时间（上海时间 UTC+8）
- UTC 时间比上海时间少 8 小时，导致比较错误

**修复**:
```php
// /workspace/src/backend/public/index.php
date_default_timezone_set(getenv('TZ') ?: 'Asia/Shanghai');
```

**影响文件**:
- `/workspace/src/backend/public/index.php`

---

## 详细问题分析

### 问题 1 详解: 时区问题

**时间线演示**:
```
当前时间: 2026-03-14 20:00:00 (上海时间)

后端计算 (PHP UTC):
  created_at = UTC 20:00:00
  expires_at = UTC 20:00:00 + 1小时 = UTC 21:00:00
  存入数据库: "2026-03-14 21:00:00" (无时区信息)

前端比较 (浏览器 上海时间):
  存储值: "2026-03-14 21:00:00" → 解析为上海时间 21:00:00
  当前时间: 上海时间 20:00:00
  结果: 21:00 > 20:00 → 未过期 ✅

但实际场景（未修复时）:
  后端计算 (PHP UTC):
    created_at = UTC 12:00:00 (使用默认 UTC 时区)
    expires_at = UTC 13:00:00
    存入数据库: "2026-03-14 13:00:00"

  前端比较 (浏览器 上海时间):
    存储值: "2026-03-14 13:00:00" → 解析为上海时间 13:00:00
    当前时间: 上海时间 20:00:00
    结果: 13:00 < 20:00 → 已过期 ❌
```

**为什么会有 8 小时差异**:
- 系统时区（Docker `TZ`）= Asia/Shanghai (UTC+8)
- PHP 内部时区（未设置）= UTC (UTC+0)
- 两者不一致，导致存储的时间比实际时间早 8 小时

### 问题 2 详解: created_at 为空

**错误原因**:
```php
// ShareModel.php
public $timestamps = false;  // ❌ 禁用自动时间戳

// 但创建时没有手动设置
$share = ShareModel::create([
    'file_id' => $fileId,
    'token' => $token,
    'password' => $hashedPassword,
    'expires_at' => $expiresAt,
    // created_at 未设置 ❌
]);
```

**正确做法**:
```php
// 1. 添加到 fillable
protected $fillable = [
    'file_id',
    'token',
    'password',
    'expires_at',
    'created_at',  // ✅
    'download_count',
];

// 2. 添加到 casts
protected $casts = [
    'file_id' => 'integer',
    'download_count' => 'integer',
    'expires_at' => 'datetime',
    'created_at' => 'datetime',  // ✅
];

// 3. 创建时手动设置
$createdAt = new \DateTime();
$share = ShareModel::create([
    'file_id' => $fileId,
    'token' => $token,
    'password' => $hashedPassword,
    'expires_at' => $expiresAt,
    'created_at' => $createdAt,  // ✅
]);
```

### 问题 3 详解: 分页实现

**数据流对比**:

**修改前**:
```
GET /api/shares
  ↓
ShareService::getList()
  ↓
ShareModel::with('file')->orderBy('created_at', 'desc')->get()
  ↓
返回: [...所有分享记录...]
  ↓
前端: 显示所有记录，无分页
```

**修改后**:
```
GET /api/shares?page=1&perPage=20
  ↓
ShareController::index()
  ↓
验证参数: page=1, perPage=20
  ↓
ShareService::getList(1, 20)
  ↓
total = ShareModel::count()  // 35
  ↓
ShareModel::with('file')
    ->orderBy('created_at', 'desc')
    ->offset(0)              // (1-1)*20 = 0
    ->limit(20)
    ->get()
  ↓
返回: {
  data: [...20条记录...],
  total: 35,
  page: 1,
  perPage: 20,
  totalPages: 2
}
  ↓
前端: 显示20条，分页组件显示"第 1/2 页"
```

**分页计算逻辑**:
```php
// 每页数量: 20
// 总记录数: 35
// 总页数: ceil(35 / 20) = 2

// 第1页:
//   offset = (1 - 1) * 20 = 0
//   limit = 20
//   记录: 1-20

// 第2页:
//   offset = (2 - 1) * 20 = 20
//   limit = 20
//   记录: 21-35 (实际15条)
```

**前端分页组件特性**:
- 页码显示: 1 ... 4 5 6 ... 20 (智能省略)
- 每页数量: 10/20/50/100 可选
- 删除最后一页数据后自动返回上一页
- 响应式设计，移动端友好

## 根因分析

### 问题 1: 缺少响应拦截器

项目中的 5 个 API 文件都创建了独立的 axios 实例，但都没有配置响应拦截器：

```
src/frontend/src/api/
├── resource.js   ❌ 缺少拦截器
├── trash.js      ❌ 缺少拦截器
├── file.js       ❌ 缺少拦截器
├── share.js      ❌ 缺少拦截器
└── upload.js     ❌ 缺少拦截器
```

### 问题 2: 重复访问 `.data`

拦截器提取了 `response.data.data` 后，API 函数又访问了 `.data`：

```javascript
// 错误的数据流
后端: { success: true, data: { files: [...] } }
  ↓
axios: response.data = { success: true, data: { files: [...] } }
  ↓
拦截器: return response.data.data = { files: [...] }
  ↓
API 函数: return response.data = undefined  // ❌ { files: [...] }.data = undefined
```

### 问题 3: Composable 检查已不存在的字段

```javascript
// useTrash.js / useShare.js
if (response.success) {  // ❌ success 字段已被拦截器移除
  trashList.value = response.files
}
```

---

## 修复方案

### 修复 1: 统一响应拦截器

为所有 API 文件添加统一的拦截器：

```javascript
api.interceptors.response.use(
  response => {
    if (response.data && typeof response.data === 'object' && 'success' in response.data) {
      return response.data.data ?? response.data
    }
    return response.data
  },
  error => {
    console.error('API Error:', error)
    return Promise.reject(error)
  }
)
```

### 修复 2: 移除 `.data` 访问

修改所有 API 函数：

```javascript
// 修改前
export const getFiles = async () => {
  const response = await api.get('/files')
  return response.data  // ❌
}

// 修改后
export const getFiles = async () => {
  const response = await api.get('/files')
  return response  // ✅
}
```

### 修复 3: 更新 Composable 函数

移除对 `response.success` 的检查：

```javascript
// 修改前
const response = await getTrashList()
if (response.success) {  // ❌
  trashList.value = response.files
}

// 修改后
const response = await getTrashList()
trashList.value = response.files || []  // ✅
```
